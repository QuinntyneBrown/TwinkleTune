# Application Shell — L1 High-Level Requirements

**Subsystem code:** AS
**Specification level:** L1 (capability / high‑level)
**Baseline:** v1.0 · **Status:** Approved
**Detailed requirements:** [L2.md](./L2.md)
**Primary dependencies:** Player Profiles (PP, guard), all screen subsystems (mount targets)

---

## 1. Purpose

The Application Shell is the frame every screen lives in. It routes between screens client‑side, guards
screens that need a profile, hosts the shared kid‑first UI primitives (bottom navigation, modals,
toasts, the mascot, and sky decor), and makes the whole thing an installable, offline‑capable Progressive
Web App. It is what lets a family "Add to Home Screen" on a tablet and have TwinkleTune feel native and
keep working with no network.

## 2. Scope

### In scope

- Hash‑based client routing, screen mounting, and clean unmount (cleanup) between screens.
- Route defaulting, unknown‑route fallback, and the profile guard.
- Shared UI primitives: bottom navigation, modal/dialog, toast, mascot, star, and decorative sky.
- The PWA manifest (installability, display mode, orientation, icons, theme colours).
- The service worker: offline caching strategy, cache versioning, and registration policy.
- Portable relative asset paths so the built app can be hosted anywhere.
- The kid‑first, responsive presentation shell (design system, large touch targets).

### Out of scope

- The content of each screen — the respective feature subsystems.
- The parent gate (a modal *instance*) — **GC** (AS provides the modal primitive).
- Server reachability probing and API calls — **FS**.

## 3. Context & dependencies

A single mount point (`#app`) hosts one screen at a time. The router parses the URL hash into a screen
name and query params, tears down the previous screen, and mounts the next. Screens that require a
profile are redirected to onboarding when none exists (PP). The service worker caches GET responses with
a stale‑while‑revalidate strategy so a previously visited app loads offline; it is registered only in
production and its failure is never fatal.

## 4. High-level requirements

| ID | Requirement | Priority | Rationale |
|----|-------------|----------|-----------|
| **AS-L1-1** | The system shall route between screens entirely on the client via the URL hash, mounting one screen at a time and cleanly tearing down the previous one. | Must | A no‑framework SPA needs deterministic navigation and no resource leaks between screens. |
| **AS-L1-2** | The system shall default and fall back sensibly — routing to home or onboarding as appropriate, guarding profile‑requiring screens, and never landing on a broken route. | Must | A child must never reach a dead or inappropriate screen. |
| **AS-L1-3** | The system shall provide consistent kid‑first navigation and shared UI primitives (bottom nav, modals, toasts, mascot, decor) across all screens. | Must | One obvious navigation model and a coherent look are core to the kid‑first UX (P5). |
| **AS-L1-4** | The system shall be installable as a PWA — standalone display, portrait orientation, app icons (including a maskable icon), and themed — so it feels native on a tablet. | Should | "Add to Home Screen" is the intended deployment on a child's device. |
| **AS-L1-5** | The system shall work offline after first visit by caching responses with a stale‑while‑revalidate strategy, versioning the cache and purging old versions. | Must | Offline‑first (P2): the app must run with no network on a tablet. |
| **AS-L1-6** | The system shall present a kid‑first, responsive, accessible shell — large rounded controls, few words, and assistive‑technology labels on interactive and decorative elements. | Should | Usability and accessibility for a young child (P5). |

## 5. Assumptions & constraints

- Routes: welcome, voice, home, songs, sing, results, tips, me, tuner, profiles, duet.
- Screens reachable without a profile: welcome, tuner, profiles.
- Cache name is versioned (`twinkletune-v1`); assets use relative paths (`base: './'`).
- The service worker is registered only in production builds and its errors are swallowed.
