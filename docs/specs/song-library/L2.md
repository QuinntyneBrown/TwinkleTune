## 2. Detailed requirements

### SL-L2-1 — Canonical song schema
- **Traces to:** SL-L1-1 · **Priority:** Must
- **Source:** `types.ts` (`Song`, `SongPhrase`, `SongNote`); mirrored by `Song.cs` records
- **Requirement:** A song shall be `{ id, title, emoji, art (1–4), bpm, difficulty (1–3), phrases[] }`,
  each phrase `{ lyric, notes[] }`, each note `{ midi, start, dur, syll }` with times in beats and
  MIDI at the base key (60 = C4). Client and server shall use this identical shape.

**Acceptance criteria**
> **GIVEN** a song object retrieved from the server
> **WHEN** it is deserialised on the client
> **THEN** its fields map one‑to‑one with the client `Song` type with no translation, and it is directly playable.

---

### SL-L2-2 — Derived song helpers
- **Traces to:** SL-L1-1 · **Priority:** Should
- **Source:** `types.ts` (`allNotes`, `songRange`, `songBeats`, `songSeconds`, `difficultyLabel`)
- **Requirement:** The library shall derive, from note data alone, a song's flattened note list, its
  MIDI range (min/max), its length in beats and seconds (rate‑aware), and a difficulty label.

**Acceptance criteria**
> **GIVEN** a song
> **WHEN** its range and length are derived
> **THEN** `songRange` returns the min and max note MIDI, `songBeats` returns the last note's end beat, and `songSeconds` = `songBeats / bpm · 60 / rate`.

> **GIVEN** a difficulty value 1, 2, or 3
> **THEN** its label is "⭐ Easy", "⭐⭐ Medium", or "⭐⭐⭐ Brave" respectively.

---

### SL-L2-3 — Bundled public‑domain catalogue
- **Traces to:** SL-L1-2, SL-L1-7 · **Priority:** Must
- **Source:** `catalog.ts`; `catalog.test.ts`; `SeedData.cs`
- **Requirement:** The product shall bundle exactly seven public‑domain songs — Twinkle Twinkle Little
  Star, Mary Had a Little Lamb, Hot Cross Buns, London Bridge, Old MacDonald, Row Row Row Your
  Boat, and Jesus Loves Me — each with unique id and each satisfying the catalogue invariants.

**Acceptance criteria**
> **GIVEN** the bundled catalogue
> **WHEN** it is loaded
> **THEN** it contains 7 songs with 7 distinct ids.

> **GIVEN** each bundled song
> **THEN** every phrase has a non‑empty lyric and ≥1 note; every note has positive duration and a non‑empty syllable; notes are ordered without overlap; the range is within C3–C6 with span ≤ 16; and the song is longer than 8 beats and under 60 seconds.

---

### SL-L2-4 — Songbook resolution order
- **Traces to:** SL-L1-3 · **Priority:** Must
- **Source:** `repo.ts` (`loadSongs`, `currentSongs`, `songsAreLive`; cache key `twinkletune:songs-cache`)
- **Requirement:** The runtime songbook shall be the family‑server list when `GET /api/songs`
  succeeds (which is then cached), otherwise the last cached list, otherwise the bundled catalogue.
  A synchronous read shall always return a usable list without awaiting the network.

**Acceptance criteria**
> **GIVEN** the server is reachable
> **WHEN** the songbook loads
> **THEN** the server list is returned, `songsAreLive()` is true, and the list is written to the cache.

> **GIVEN** the server is unreachable but a cache exists
> **WHEN** the songbook loads
> **THEN** the cached list is returned and `songsAreLive()` is false.

> **GIVEN** the server is unreachable and no cache exists
> **THEN** the bundled seven are returned.

### SL-L2-5 — Offline songbook indication
- **Traces to:** SL-L1-3 · **Priority:** Should
- **Source:** `frontend/apps/game/src/screens/songs.ts` (offline banner; live‑only affordances hidden)
- **Requirement:** When the songbook is not live (server unreachable), the song list shall show an
  offline notice and shall omit server‑only affordances (family‑score board, duet), while keeping all
  songs singable.

**Acceptance criteria**
> **GIVEN** the songbook is serving cached/bundled content offline
> **WHEN** the song list renders
> **THEN** an offline banner is shown, high‑score and duet buttons are absent, and every song can still be started.

---

### SL-L2-6 — Song lookup and id origin detection
- **Traces to:** SL-L1-3 · **Priority:** Must
- **Source:** `repo.ts` (`getSongById`, `isServerSongId` GUID regex)
- **Requirement:** The library shall resolve a song by id from the current songbook (falling back to
  the bundled catalogue) and shall classify an id as server‑originated (GUID) versus bundled (slug).

**Acceptance criteria**
> **GIVEN** a GUID song id
> **WHEN** it is classified
> **THEN** `isServerSongId` returns true.

> **GIVEN** a bundled slug id such as `twinkle`
> **THEN** `isServerSongId` returns false, and `getSongById('twinkle')` still resolves the bundled song.

---

### SL-L2-7 — Song validation rule‑set (client)
- **Traces to:** SL-L1-4 · **Priority:** Must
- **Source:** `types.ts` (`validateSong`)
- **Requirement:** The client shall reject a song that violates any invariant, returning a list of
  friendly messages: missing/over‑long title (>80), missing emoji, art outside 1–4, BPM outside
  40–220, difficulty outside 1–3, zero phrases, a phrase with no lyric or no notes, a note with
  non‑positive duration, a note with an empty syllable, a note MIDI outside 48–84, a note overlapping
  the previous note, or a melody span exceeding 16 semitones.

**Acceptance criteria**
> **GIVEN** a song with a note at MIDI 90
> **WHEN** it is validated
> **THEN** validation fails with a message that the note is outside 48–84 (C3–C6).

> **GIVEN** a song whose second note starts before the first note ends
> **THEN** validation fails with an overlap message.

> **GIVEN** a fully well‑formed song
> **THEN** validation returns no errors.

---

### SL-L2-8 — Validation parity (server)
- **Traces to:** SL-L1-4 · **Priority:** Must
- **Source:** `SongValidator.cs` (`MinMidi=48`, `MaxMidi=84`, `MaxSpan=16`)
- **Requirement:** The server shall enforce the same invariants as the client (same thresholds:
  title ≤ 80, BPM 40–220, art 1–4, difficulty 1–3, MIDI 48–84, span ≤ 16, ordered non‑overlapping
  notes, non‑empty lyrics and syllables), so any song the server accepts the client can render.

**Acceptance criteria**
> **GIVEN** a song the client validator rejects for span > 16
> **WHEN** the same song is submitted to the server
> **THEN** the server also rejects it, citing the span.

> **GIVEN** a song both validators accept
> **THEN** it saves on the server and plays on the client identically.

---

### SL-L2-9 — Song CRUD endpoints
- **Traces to:** SL-L1-6 · **Priority:** Must
- **Source:** `SongsController.cs`, `SongService.cs`
- **Requirement:** The server shall expose `GET /api/songs`, `GET /api/songs/{id}`,
  `POST /api/songs`, `PUT /api/songs/{id}`, `DELETE /api/songs/{id}`, returning 200/201/204 on
  success and 404 when a targeted song does not exist; title and emoji shall be trimmed on save and
  `UpdatedAt` set.

**Acceptance criteria**
> **GIVEN** a valid new song
> **WHEN** it is POSTed
> **THEN** the server responds 201 Created with the stored song (a GUID id, `isSeed=false`).

> **GIVEN** a non‑existent song id
> **WHEN** it is updated or deleted
> **THEN** the server responds 404.

> **GIVEN** an existing song
> **WHEN** it is deleted
> **THEN** the server responds 204 and the song no longer appears in the list.

---

### SL-L2-10 — Validation error surfacing
- **Traces to:** SL-L1-6 · **Priority:** Must
- **Source:** `SongsController.cs` (`BadRequest(new { errors })`); `client.ts` (`ApiError.errors`)
- **Requirement:** When a create or update fails validation, the server shall respond 400 with an
  `errors` array of friendly messages; the client shall surface these messages to the grown‑up.

**Acceptance criteria**
> **GIVEN** a song submission with an empty title and a note out of range
> **WHEN** it is POSTed
> **THEN** the response is 400 with an `errors` array containing a title message and a range message.

---

### SL-L2-11 — Seed song flagging and protection
- **Traces to:** SL-L1-6 · **Priority:** Should
- **Source:** `SeedData.cs` (`IsSeed = true`); `SongService.UpdateAsync` (preserves `IsSeed`); `managers.ts` delete‑confirm copy differs for seeds
- **Requirement:** Built‑in songs shall be marked as seed content; updating a seed song shall preserve
  its seed flag; deletion of a seed song shall be surfaced with a warning that a built‑in song will be
  removed from the family songbook.

**Acceptance criteria**
> **GIVEN** a seed song
> **WHEN** it is edited and saved
> **THEN** the stored song retains `isSeed = true`.

> **GIVEN** a seed song
> **WHEN** deletion is requested in the manager
> **THEN** the confirmation explains it is a built‑in song being removed from the songbook.

---

### SL-L2-12 — Songbook ordering
- **Traces to:** SL-L1-6 · **Priority:** Could
- **Source:** `Repositories.cs` (`SongRepository.GetAllAsync`: `OrderBy Difficulty ThenBy Title`)
- **Requirement:** The server song list shall be ordered by ascending difficulty then title, so
  easier songs appear first.

**Acceptance criteria**
> **GIVEN** songs of mixed difficulty
> **WHEN** the list is fetched
> **THEN** songs are ordered by difficulty ascending, ties broken alphabetically by title.

---

### SL-L2-13 — Phrase persistence as JSON
- **Traces to:** SL-L1-1 · **Priority:** Should
- **Source:** `AppDbContext.cs` (Phrases stored via JSON value converter)
- **Requirement:** A song's phrases/notes shall persist as a single JSON document mirroring the client
  shape, rather than as note‑per‑row tables, so the server and client representations remain identical.

**Acceptance criteria**
> **GIVEN** a song saved with several phrases
> **WHEN** it is reloaded from the database
> **THEN** its phrases and notes deserialise to the same structure that was saved.

---

### SL-L2-14 — Browse and difficulty filtering
- **Traces to:** SL-L1-5 · **Priority:** Should
- **Source:** `frontend/apps/game/src/screens/songs.ts` (filter chips 0–3; per‑card duration and difficulty label)
- **Requirement:** The song list shall present each song with its emoji art, title, estimated
  duration, and difficulty label, and shall offer filter chips — All, Easy, Medium, Brave — that show
  only the matching songs without re‑fetching.

**Acceptance criteria**
> **GIVEN** the song list with the "All" filter active
> **WHEN** the "Brave" filter is selected
> **THEN** only difficulty‑3 songs are shown, and re‑selecting "All" shows every song again.

---

### SL-L2-15 — Seed parity between bundle and server
- **Traces to:** SL-L1-7 · **Priority:** Should
- **Source:** `SeedData.cs` (comment: note‑for‑note identical to `frontend/apps/game/src/songs/catalog.ts`)
- **Requirement:** The server's seed songs shall match the bundled catalogue note‑for‑note, so the seven
  songs are identical whether served online or bundled offline.

**Acceptance criteria**
> **GIVEN** a freshly seeded server and the bundled catalogue
> **WHEN** the same titled song is compared from each source
> **THEN** its phrases, lyrics, and notes are identical.
