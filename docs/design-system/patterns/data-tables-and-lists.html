Pattern

Data tables and lists

Lists in TwinkleTune are rows of big friendly cards, not data grids. Songs, family content, high scores and mastered songs each have a row shape that leads with an emoji, says one thing clearly, and puts the action where a thumb expects it.

Overview

Four row shapes cover every list in the mocks. Each starts with an emoji or art tile so a child who cannot read yet still recognises the row.

  • Song rows (.song): art, title, meta (duration, difficulty, ✓ In your key, 🏆 and Duet mini buttons) and a round blue ▶. Preceded by the pink Sing it again! card and followed by the dashed gift note.
  • Manager rows (.mgr-row): emoji, name (with built-in where it applies), ✏️ edit and 🗑️ delete icon buttons. Grown-ups only.
  • Board rows (.board-row): medal, singer avatar, name, stars, percentage. One row per family singer, her best on that song.
  • Mastered rows (.mastered): emoji, song title, gold stars. Read-only, on Me.

The table, list and pagination components are not in the mocks yet; they are added for wide grown-up views of family data (all high scores across songs, every singer) and follow the same tokens.

Responsive behaviour

  • Rows fill the 470px column; the art tile and ▶ keep their size and the title area flexes. Long titles wrap to two lines, never truncate.
  • Song meta wraps onto a second line at narrow widths, with the 🏆 and Duet buttons staying together.
  • Manager and board rows live in a 440px dialog; names flex, buttons and numbers keep their width.
  • Tables scroll horizontally inside .table-wrap below their natural width; the first column is the row header so each row still reads on its own. Below 640px prefer the row shapes above to a table.

Accessibility

  • Semantics: lists are <ul> or, for rankings, <ol>; song rows are <article> with the title as text. The mocks use bare <div> rows; the system keeps the class names and adds list semantics.
  • Action names include the item: Sing Twinkle Twinkle Little Star, High scores for …, Duet …, Edit Unicorn, Delete Unicorn. A screen-reader user tabbing through hears which row each button belongs to.
  • Stars and medals have words: role="img" + aria-label="2 of 3 stars"; medals read First, Second, Third. The ✓ In your key pill explains itself in text; its title (Moved 3 notes higher for you 💙) is a bonus, not the only source.
  • Tables have a <caption>, scope on headers and right-aligned numeric columns; sortable headers use a button inside th[aria-sort].
  • Touch: ▶ is 52px; manager icon buttons 44px with 8px between them; mini buttons at least 24px tall with 8px spacing (D23).

Content

  • Song titles are the song's real public-domain title; meta uses symbols plus a word: ⏱ 0:29, ⭐ Easy, ⭐⭐ Medium, ⭐⭐⭐ Brave.
  • Board percentages are the landed share of her best run. Stars are always shown as filled plus pale (★★☆), never as a number out of three.
  • Managers mark origin with a quiet built-in tag; family songs carry no tag.
  • The list's closing note is an invitation (New songs land every Friday!, Grown-ups can add new songs in the Grown-Ups Corner!), not a count.
