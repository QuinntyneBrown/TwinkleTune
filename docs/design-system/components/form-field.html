Form field

The wrapper every input uses: label, control, hint, then a gentle error or a counter, always in that order and always 8px apart. Errors start with a blue heart, never a red cross.

Overview

A form field is not a control; it is the arrangement around one. Use it whenever an input needs more than its label: a hint about format, a message when something is missing, a character count. It keeps every grown-up dialog spaced the same and wires the messages to the control so screen readers hear them.

The mocks place .field-label and the control as loose siblings and have no per-field messages: validation is a pink toast (singer and avatar editors) or one list at the bottom of the dialog (song editor). The .form-field wrapper, .field-hint, .field-error, .field-success and .field-counter are new in the system and close that gap. The messages themselves are documented as inline messages.

Child screens rarely need any of this. Welcome's name card is a label and a field, and an empty name simply becomes Superstar: nothing a child types is ever "invalid".

Anatomy

  1. Label.field-label: Baloo 2 bold 16px. In a .form-field its own margins are removed and the wrapper's 8px gap takes over.
  2. Optional markerA neutral .pill reading optional. Mark the rare optional field, not the many required ones.
  3. ControlAny text field, textarea, select, slider or file upload.
  4. Hint.field-hint, --text-body-sm in --color-fg-muted. Stays visible while the error shows.
  5. Error.field-error, --text-body-sm in --color-danger-fg, led by a 💙 drawn in CSS. Appears only after a save attempt.
  6. Counter.field-counter, caption size, right-aligned. Only where a limit is likely to be reached.

When messages appear

  • Errors appear when the grown-up presses Save, never while typing the first time. After that, an error clears as soon as the field is fixed.
  • Success is rare: only for a check worth confirming (a title not already used). Never tick every valid field.
  • Nothing is cleared on a failed save; the song editor mock keeps every character.

Responsive behaviour

  • The wrapper is a column at every width; parts never sit side by side.
  • Hints and errors wrap freely; keep each to one sentence so they fit two lines at 320px.
  • Two wrappers can share a row in a .field-pair or .form-row--2; see form layout.

Theming

Messages use status roles that are tuned per theme: --color-fg-muted for hints, --color-danger-fg for errors, --color-success-fg for success. The 💙 before an error is an emoji and looks the same in both studios; it carries the brand's "this is gentle" signal.

Accessibility

Role and pattern

No role: a plain <div> grouping a native control with its texts. Wiring follows the WAI Forms tutorial (labels, instructions, notifications). Related controls that share one question go in a fieldset.form-group with a <legend> instead.

Keyboard

KeyAction
Tab / Shift+TabMoves between controls. Labels, hints and messages are not focusable.
Click / tap on the labelFocuses the control (native <label for>).

Focus

Focus belongs to the control. After a failed save, focus moves to the validation summary (see form layout), whose links move focus to each field.

Labelling

  • <label for> names the control. The optional marker is part of the label text.
  • aria-describedby lists the hint id, then the error id: the hint is read first, then what to fix.
  • aria-invalid="true" goes on the control while its error shows, and comes off with it.
  • The counter is not in a live region (it would chatter on every key); maxlength already stops input at the limit.

Motion

Messages appear without animation, so nothing shifts while reading. No shaking.

Touch

The label is a tap target for its control, which makes small controls (checkbox, radio) easier to hit.

Content

  • Hints answer "what goes here?" before it is asked: One emoji, like 🐯 or 🦒.
  • Errors follow one formula: what the thing needs, plus how to give it. An avatar needs a name, like Tiger., Tempo must be between 40 and 220 BPM., Every singer needs a name! 💙. Never Required, Invalid input, Error or Wrong.
  • Do not repeat the 💙 in the text of a .field-error; the CSS adds it.
  • Optional is the only marker. No asterisks.
  • Counters show used / limit: 12 / 30.
