Container

The layout primitives every screen is built from: the one centred child column, the wide grown-ups container, and stack, cluster and grid for arranging what goes inside.

Overview

Containers set width and rhythm; they draw nothing. Every child screen is one .screen: a single centred column, 470px at most, with 20px side margins and room at the bottom for the floating bottom nav. That one column is why buttons and cards never rearrange between a phone and a tablet.

  • Screen (.screen) is the child column, used by every page mock. .screen--center centres a celebratory screen (Welcome, Results); .screen--nonav drops the bottom-nav clearance (Sing, Find My Voice).
  • Container (.container) is the wide frame for grown-up and marketing pages, up to 1280px. .container-screen narrows it back to the child column.
  • Stack (.stack, .stack-sm, .stack-lg) spaces children vertically: 16px by default, 8px or 24px.
  • Cluster (.cluster) lays children in a wrapping row with a 12px gap: song meta, button pairs, chips.
  • Grid (.grid) is the responsive column grid: 4, 8 or 12 columns with the layout gutter. .grid-auto fills as many equal tracks as fit, as the profile grid does.

The screen column and the screen-specific grids (.tiles, .badges, .profile-grid) come from the mocks. .container, .stack, .cluster, .grid and .grid-auto are not in the mocks yet; they are added for the Grown-Ups Corner, the family-server managers and marketing, and generalise what the screens already do by hand.

Anatomy

  1. Margin--layout-margin: 20px on phones, 32px from 768px, 48px from 1024px. The screen's side padding.
  2. Column--layout-columns: 4, then 8 from 768px, then 12 from 1024px. Child screens use the single 470px column regardless.
  3. Gutter--layout-gutter: 16px, then 24px, then 32px. Stacks and clusters use the spacing scale instead.

States

Layout primitives have no interactive states.

Responsive behaviour

  • Mobile first. Breakpoints are --layout-breakpoint-sm 640px, -md 768px, -lg 1024px, -xl 1280px. Columns, gutter and margin step up at 768px and 1024px.
  • The child column never widens. On a tablet the sky fills the rest of the screen; the column stays centred so a child's thumb finds the same buttons.
  • .screen pads 28px top, 20px sides and 128px bottom (--layout-bottomnav-clearance) so the last card scrolls clear of the floating nav.
  • .grid-auto uses min(100%, …) so a single track never overflows a 320px screen.
  • Content reflows to one column at 320px CSS width (WCAG 1.4.10); nothing scrolls horizontally except a .table-wrap or a .chip-row.

Theming

Containers read only layout and spacing tokens, which are the same in both themes. The page sky behind .screen comes from --gradient-sky on body, which the night studio swaps for the deep gradient.

/* A looser stack for a marketing section */
.feature-list { --stack-gap: var(--space-10); }

Accessibility

Role and pattern

No APG widget applies; containers are structure. .screen is the <main id="main"> landmark that the skip link targets (APG Landmark Regions). Stacks, clusters and grids are plain <div>s, or <ul> when the children are a list.

Keyboard

KeyAction
TabFollows DOM order. Grids and clusters never reorder visually (no order, no row-reverse), so focus moves left to right, top to bottom.

Focus

Containers are never focusable. Leave room for focus rings: a 3px ring at 3px offset needs 6px of clear space, which the 8px minimum gap provides.

Labelling

One <main> per page. A grid of singers or badges that a screen reader should hear as a set is a <ul> with role="list" kept (some browsers drop it with list-style: none).

Contrast

Body text on the page sky
Secondary text on the page sky

Motion

Containers do not animate. Children entering a stack use the screen's staggered rise, removed under prefers-reduced-motion.

Touch

Keep at least 8px between adjacent targets in a cluster (--cluster-gap never below --space-2), so targets smaller than 52px still meet WCAG 2.5.8 spacing.

Content

Layout primitives carry no copy of their own.
