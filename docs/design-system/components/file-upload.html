File upload

A singer's photo, picked from the device and kept on the family server. The mocks use the plain file input; the system adds a dashed drop zone around the same input.

Overview

There is one upload in TwinkleTune: a singer's photo, which replaces her emoji avatar (Mum has one in the mocks). It is offered in the singer editor under the avatar picker as …or use a photo 📸. Photos live only on the family server, at most 2 MB, as JPEG, PNG or WebP, and never go anywhere else.

  • Plain (.photo-input) is the mock: the browser's own file button, bold, never wider than the dialog.
  • Drop zone (.file-drop) wraps the same input in a dashed sunken box that also accepts a dragged file. Not in the mocks yet; added for the family-server managers on wider screens, where dragging a photo from the desktop is natural.

The input is always the real control; the drop zone is an enhancement. Without a family server there is nowhere to keep a photo, so the photo option is not shown at all (offline first: the emoji avatars always work).

Anatomy

  1. Zone3px dashed --color-border-strong, --radius-lg, --color-bg-surface-sunken, 20px padding. Dashed says "put something here", like the add-singer card.
  2. Emoji📸 at --font-size-4xl, decorative.
  3. LabelA visible <label for> naming what is uploaded.
  4. File inputThe browser's button and file name. It takes focus and the keyboard.
  5. HintFormats and size in --text-body-sm, linked by aria-describedby.

Drop zone

📸 Drop a photo here or pick one. JPEG, PNG or WebP, up to 2 MB.
Not in the mocks yet. The whole zone accepts a drop; the input inside still works with keyboard and tap.

Sizes

One size: full width of its column; the zone grows with its content.

States

Dragging and failed are set by script with data-state on the zone. Focus is :focus-within on the zone (tab into the live examples to see it). A chosen file shows its name and a preview in the avatar; the upload itself happens on Save, so uploading is the Save button's busy state.

Responsive behaviour

  • On phones and tablets (the app's usual home) dragging is rare; the plain input is enough and opens the camera roll or camera.
  • The drop zone fills its column and centres its contents. The file input is capped at 100% width so a long file name never widens the dialog.
  • At 320px the zone's copy wraps; keep it to one short sentence plus the hint.

Theming

Semantic tokens only: --color-bg-surface-sunken and --color-border-strong at rest, --color-accent and --color-accent-subtle while dragging, --color-danger-bg, --color-danger-solid and --color-danger-fg when failed. The file button itself is the browser's; color-scheme on the theme root keeps it readable in the night studio.

Accessibility

Role and pattern

The native <input type="file"> is the control and has its own button role and file-name announcement. No APG pattern; the drop zone adds nothing a keyboard or screen-reader user needs, which is the point. See the WAI Forms tutorial for labelling.

Keyboard

KeyAction
Tab / Shift+TabMoves to and from the file input.
Enter, SpaceOpens the device's file or photo picker.
Esc (in the picker)Closes the picker without changing the chosen file.

Focus

The input's own focus is drawn on the whole zone (.file-drop:focus-within) with the shared ring, so the large target shows it.

Labelling

  • A visible <label for>. The mock names the input only with aria-label="Photo" and leaves the heading …or use a photo 📸 loose; make the heading the label.
  • Formats and size limit in a hint linked with aria-describedby, so they are heard before choosing.
  • A failed check sets aria-invalid="true" and puts the message in the label or a linked .field-error; announce it once through the dialog's status region.

Motion

State changes are instant. No progress animation: photos are small and the Save button's spinner covers the wait.

Touch

The browser's file button is at least 44px tall on touch devices; the drop zone around it is larger but only the input opens the picker, so a stray tap on the zone does nothing surprising.

Content

  • Say what the photo is for and where it goes: …or use a photo 📸, It stays on your family server. Privacy is a product principle, so say it at the moment of upload.
  • Give the rules before choosing: formats and up to 2 MB.
  • A failed check says what to do next, gently: That photo is a bit big. Pick one under 2 MB., That file isn't a photo we can use. Try a JPEG, PNG or WebP. Never the browser's raw text (Failed to fetch).
  • If the family server is unreachable on Save: The family server isn't answering. Your photo is still here; try Save again in a moment.
