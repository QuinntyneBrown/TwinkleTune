Tooltip

A tooltip is a small dark label that explains a control on hover and keyboard focus: why a song is "In your key", what the ⋯ button does. It adds a detail; it never holds the only copy of something important.

Overview

Not in the mocks yet as a component; added for the Grown-Ups Corner, family-server managers and marketing. The mocks use the browser's title attribute in its place, for example "Moved 3 notes higher for you 💙" on every ✓ In your key pill and on the Sing key label. A title never shows on touch and is unreliable for keyboard and screen-reader users, so the system replaces it with this tooltip, which opens on hover and focus.

  • Use a tooltip for a short, non-essential detail about a control that already has a name.
  • Children use tablets, so on child screens the same words must also exist somewhere touch can reach: a dialog (Song tuned for you), Twinkle's bubble, or visually hidden text.
  • Never put a link, button or anything interactive inside a tooltip; use a dialog instead.
  • Never use a tooltip for a gentle error or hint about a field; use an inline message.

Anatomy

  1. Label--text-label (14px extra-bold) in --color-fg-inverse on --color-bg-inverse, 4 × 12px padding, --radius-md, one line.
  2. ArrowA 4px triangle in the same inverse colour, pointing at the trigger's centre.
  3. TriggerAny focusable control, wrapped in .tooltip-wrap. It points at the tooltip with aria-describedby.

The tooltip sits 8px above the trigger, centred, at --z-tooltip, with --shadow-3 and pointer-events: none so it never blocks a tap.

Variants

Visible tooltips are forced here with data-state="visible"; .tooltip--static shows one in the page flow.

Edit Frère Jacques

Sizes

Tooltips have one size: label type, one line.

States

A tooltip has two states, hidden and visible. It becomes visible when its trigger is hovered or focused (.tooltip-wrap:hover, :focus-within), after a 400ms delay (--duration-slow), and hides at once when both end.

The inverse pair flips with the theme: deep navy with white text in the sky studio, pale with navy text in the night studio, so the tooltip always stands out from the surface below.

Responsive behaviour

  • A tooltip stays on one line and no wider than the viewport minus 32px; text longer than about 40 characters belongs in a dialog or bubble.
  • If it would leave the top of the viewport it flips below the trigger; near a side edge it shifts inward and the arrow stays over the trigger.
  • On touch devices there is no hover. A long press must not be the only way to read it, which is why child screens repeat the words elsewhere.

Theming

The tooltip reads --color-bg-inverse, --color-fg-inverse, --shadow-3, --radius-md and --text-label. It has no component tokens and no tone variants; a coloured tooltip would read as a status message.

Accessibility

Role and pattern

APG Tooltip. The tooltip has role="tooltip" and an id; the trigger references it with aria-describedby, so the text is read as a description after the control's name. A tooltip is never the name itself: an icon button still has its own aria-label.

Keyboard

KeyAction
TabFocusing the trigger shows the tooltip after the delay.
EscHides the tooltip without moving focus (WCAG 1.4.13, dismissible).
Shift+Tab / blurHides the tooltip.

Focus

Focus stays on the trigger; the tooltip is never focusable. A non-interactive trigger such as a pill gets tabindex="0" only when it has a tooltip, so keyboard users can reach the description.

Labelling

Write the tooltip as a description, not a repeat of the name: for ✏️ named Edit Ada, a tooltip that also says Edit Ada is fine for sighted mouse users but should not be wired with aria-describedby (it would be read twice). Hoverable (WCAG 1.4.13): the label has pointer-events: none, so moving the pointer onto it ends the hover. Keep tooltips to a few words that can be read without moving the pointer, and keep the same words reachable elsewhere; a longer tooltip that must stay open under the pointer needs a hoverable modifier the stylesheet does not have yet.

Motion

Fades in over --duration-base after a --duration-slow delay; hides immediately. Under reduced motion it appears without the fade.

Touch

Tooltips are not targets (pointer-events: none), so they never steal a tap meant for the control below. Their content must be available another way on touch.

Content

  • One short phrase, no full stop: Moved 3 notes higher for you 💙, Only grown-ups can change this.
  • Explain, never warn: a tooltip is not where bad news goes, and there is no bad news for a child.
  • Use the domain words: notes higher (Shift), voice range, family server.
  • Shortcuts go in a trailing <kbd>; grown-up and desktop only.
