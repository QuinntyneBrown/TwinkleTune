Text field

A sunken well with a strong edge and big, bold type. The child's name field on Welcome is the largest; grown-up fields in the family-server dialogs are the same shape at body size.

Overview

Use a text field when the answer is a few words someone types: a singer's name, a song title, a tempo, a room code. If there are only a handful of possible answers, offer them as buttons instead (the avatar picker, a select or a radio group): typing is the hardest thing a young child does in the app.

  • Child field (.name-input) is the big one: 24px extra-bold type in a 24px-radius well. It appears twice: My name is… on Welcome and Name in the singer editor. One per screen. The same class also styles the Duet lobby's song picker (see select).
  • Grown-up field (.field) is the compact one for the family-server editors: song title, emoji, tempo, avatar name. It sits behind the parent gate, so a child never has to fill it in.
  • Room code (.name-input.code-input) is the child field tuned for four capital letters, centred and widely spaced, on Duet's join screen. Its partner is the duet code display.

Wrap the field in a form field to add a hint, an error or a counter, and lay several out with form layout. Multi-line input is the textarea.

Anatomy

  1. LabelAlways visible, above the field. Baloo 2 bold, 18px on child screens (.name-card label), 16px for grown-ups (.field-label). It is the accessible name.
  2. Placeholder (optional)A hint of what to type, in --color-fg-subtle. It disappears on the first letter, so it never carries anything she needs to remember.
  3. Well--color-bg-surface-sunken, so the field reads as a slot to fill rather than a card to tap. Child: 16 × 20px padding, --radius-lg. Grown-up: 8 × 12px padding, --radius-md.
  4. Edge3px (--border-width-thick) in --color-border-strong, 3.7:1 against the well. Turns blue on hover, focus-ring blue with a doubled edge on focus, danger red when invalid.

Variants

Child field

Welcome's name card: a white card on the sky holding one big field.
HTML
<div class="card name-card">
  <label for="kid-name">My name is…</label>
  <input class="name-input" id="kid-name" type="text" maxlength="20"
         autocomplete="off" placeholder="Type your name">
</div>

Grown-up field

The song editor's title and tempo. type="number" keeps the same look and adds a numeric keyboard.
HTML
<label class="field-label" for="song-title">Title</label>
<input class="field" id="song-title" type="text" maxlength="80">
<label class="field-label" for="song-bpm">Tempo (BPM)</label>
<input class="field" id="song-bpm" type="number" min="40" max="220" value="100">

Room code

Type the room code 🔑

Duet join: four letters, uppercase as she types, centred with 0.4em tracking so each letter matches a tile on the host's screen.
HTML
<input class="name-input code-input" maxlength="4" autocapitalize="characters"
       autocomplete="off" spellcheck="false" placeholder="ABCD" aria-label="Room code">

Sizes

Grown-up fields come in three sizes; the large one is exactly the child field's look, for the rare grown-up screen that has a single question. Child screens only ever use .name-input.

.field-sm for dense manager rows, .field in dialogs, .field-lg (same as .name-input) for a single big question.

States

Hover and focus are forced here with data-state; real fields get them from :hover and :focus. Invalid is aria-invalid="true", which the mocks do not set yet (see Sources).

Both themes

  • Focus swaps the edge to --color-focus-ring and adds a 2px ring outside it, so the edge reads as 5px. The field does not use the shared offset outline because the caret is already inside it and the doubled edge is enough.
  • Invalid only changes the edge. It is never shown alone: the message under the field (a field error) says what to do. On a child screen nothing is ever invalid: an empty name on Welcome simply becomes Superstar.
  • Disabled greys the text and flattens the well to --color-bg-subtle. Avoid it; hide a field that cannot be used instead.
  • Read-only (grown-up only) keeps the text readable, flattens the well and dashes the edge, so it reads as a value to copy, not a slot to fill.

Responsive behaviour

  • Fields are always full width of their container. The child field's card stops at --size-form-max (360px), matching the Welcome button beneath it.
  • In dialogs, fields fill the dialog (340px standard, 440px for the song editor). Two short fields can share a row in a .field-pair; see form layout.
  • Type never shrinks below 16px in a grown-up field, so iOS does not zoom on focus. .field-sm (14px) is only for desktop-width manager rows.
  • The room code is sized for four letters at 28px with wide tracking; at 320px it still fits with room to spare. Do not use .code-input for anything longer.

Theming

Text fields read semantic tokens directly; there are no component tokens. The well is --color-bg-surface-sunken, the edge --color-border-strong, the text --color-fg-default, the placeholder --color-fg-subtle. In the night studio the well darkens below its card, so it still reads as recessed, and the edge lightens to keep 3:1.

/* A field on a pink card keeps its own well; do not tint the field. */
.again-card .field { background: var(--color-bg-surface-sunken); }

Accessibility

Role and pattern

Native <input>; no ARIA role. There is no APG widget pattern for a plain text box; follow the WAI Forms tutorial for labels, instructions and validation.

Keyboard

KeyAction
Tab / Shift+TabMoves into and out of the field in DOM order.
EnterSubmits the enclosing form (Welcome: same as Let's Sing!; room code: same as Join the duet!).
↑ / ↓On type="number" (tempo), steps the value by 1 within min/max.
EscInside a dialog, closes the dialog (the field keeps no state of its own).

Focus

Focus is shown on the field's own edge: --color-focus-ring plus a 2px ring, at least 3:1 against the well, the card and the dialog. Focus never moves into a field by itself on child screens, because the on-screen keyboard would cover the screen before she has read it.

Labelling

  • Every field has a visible <label for>. Placeholders (Type your name, Tiger) are examples, never the label.
  • The room code is named by aria-label="Room code", and its visible heading Type the room code contains that name, so voice control works.
  • Hints and errors join the name through aria-describedby; see form field.
  • Singer names use autocomplete="off": on a shared family tablet, autofill would offer one child another child's name.

Motion

The edge colour changes instantly; no transition is needed. The only motion near a field is the .shake nudge some apps use for wrong input, and TwinkleTune never uses it on a field: shaking reads as "wrong".

Touch

The child field is about 70px tall and the grown-up field 44px (16px type plus padding and edges), both above the 44px comfortable target. The whole label is also a tap target for its field.

Content

  • Child labels are the start of a sentence she finishes: My name is…. Grown-up labels are a plain noun: Name, Title, Emoji, Tempo (BPM).
  • Placeholders show a real example (Tiger, 🐯, ABCD) or a short instruction (Type your name). Never put rules there.
  • Put units in the label, not after the value: Tempo (BPM).
  • Set maxlength to the server's limit (name 20, avatar name 30, title 80, emoji 4, code 4) so nothing she types is rejected later.
  • When something is missing, say what to add, kindly: Every singer needs a name! 💙, A song needs a title.. Never Required, Invalid or Error.
