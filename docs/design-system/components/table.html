Component · Data display

Table

Rows and columns for comparing family data: high scores across songs, the songbook with its details. The child-facing song board stays a simple ranked list; the full table is for grown-ups.

Overview

Use a table when a grown-up compares the same facts across many items: every singer's best on every song, or the songbook with notes, phrases and who added it. Use a list when there is one thing to read per row, and never put a table on a child screen.

  • Song board (.board-row) is in the mocks: the 🏆 dialog lists each singer's best on one song, ranked 🥇🥈🥉, with stars and a percentage. It reads as a list of three or four rows and stays that way for children.
  • Data table (.table in a .table-wrap) is not in the mocks yet; it is added for the Grown-Ups Corner and the family-server managers: family high scores across all songs, the songbook overview. Variants: default, dense (.table-dense), sortable (aria-sort) and selectable rows (aria-selected).

The server owns high scores only (upsert-if-better per singer and song). Sparkles, badges and day streaks stay on each device, so no table ever shows them for the whole family.

Anatomy

  1. CaptionBaloo 2 bold --font-size-lg. The table's name; always present, never only a heading above.
  2. Header row--text-overline, uppercase, --color-fg-muted on --color-bg-surface-sunken; scope="col".
  3. Row headerThe first cell names the row (<th scope="row">): the singer.
  4. Numeric cell.num-cell: right-aligned, tabular figures, so 81% and 95% line up.

The wrapper (.table-wrap) is a white --radius-lg surface with --shadow-1 that scrolls sideways on narrow screens. Cells pad 12 × 16px and are separated by --color-bg-subtle hairlines.

Responsive behaviour

  • Below 640px a data table scrolls sideways inside .table-wrap; the page never does. Give the wrapper tabindex="0", role="region" and a label so keyboard users can scroll it.
  • With three columns or fewer, prefer a list or description list on phones instead of a scrolling table.
  • The song board never scrolls sideways: its rows are flex, and the name column (.nm) absorbs the width.

Theming

The table reads --color-bg-surface (wrap), --color-bg-surface-sunken (header and hover), --color-bg-subtle (row lines), --color-accent-subtle (selected), --color-fg-default and --color-fg-muted. Song board rows read --color-bg-subtle for their 2px separator and --color-fg-muted for the percentage. All rise correctly in the night studio because they are surface roles.

Accessibility

Role and pattern

A native <table> with <caption>, scope="col" headers and a scope="row" first cell (APG Table; sortable headers follow the sortable table example). It is a static table, not a grid: arrow keys are not captured. The song board is an <ol> because rank is its order; the mock's bare <div>s should become list items.

Keyboard

KeyAction
TabMoves to the scroll region (when it overflows), then to each sort button and row control in order.
Enter, SpaceOn a sort button: sorts by that column, toggling ascending and descending.
← →Scrolls a focused .table-wrap sideways (browser default).

Focus

Sort buttons and row controls take the shared 3px ring. The scroll region shows the ring around the whole wrapper. Sorting keeps focus on the header button just pressed.

Labelling

The caption names the table. Only the sorted column carries aria-sort="ascending|descending"; others drop the attribute or use none. The ▲▼ arrows are CSS content, so the state is announced from aria-sort, not from the glyph. Medals and text stars are paired with visually hidden words ("First:", "3 of 3 stars").

Selection is never colour alone: a selectable table has a checked checkbox in the first column alongside the tint.

Motion

Row hover background transitions over --duration-base when added; re-sorting does not animate rows. Skeletons stop shimmering under reduced motion.

Touch

Sort buttons and row controls are at least 44px tall (--target-comfortable); dense tables with controls keep 44px rows.

Content

  • Captions and headers are short nouns: Family high scores, Singer, Song, Best.
  • Percentages are whole numbers with a % sign; stars always come with the number in words for screen readers.
  • Empty and failed copy comes from the song board: No scores yet — be the first! ⭐, Scores need the family server 📡. Never "Error" or "Failed to fetch" (D19).
  • No "worst", "lowest" or last-place column. The board shows bests, so everyone on it did something great.
