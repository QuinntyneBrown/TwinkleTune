Inline message

One short line under a field that helps before, kindly says what to change, or confirms it worked. It sits right where the grown-up's eyes already are, and stays until the field is fixed.

Overview

Use an inline message for anything about one field: what to type (Middle C is midi 60), what to change (Tempo must be between 40 and 220 BPM), or that it is fine (Photo ready: 1.2 MB of 2 MB.). It is the field-level partner of the validation box, which lists every problem at once.

Not in the mocks yet. The app validates the singer and avatar editors with a toast and the song editor with one list, and marks no field. Inline messages are added for the Grown-Ups Corner and the family-server editors so each problem is shown and announced at its field; the validation box stays as the summary.

  • Don't use it for news about the whole screen: that is an alert or a toast.
  • Don't put it on child screens. A child's only field, her name on Welcome, never errors: an empty name is fine and Twinkle calls her "Superstar".
  • The message lives inside a form field, which owns the spacing between label, control and message.

Anatomy

  1. MarkerGenerated by CSS: 💙 for an error, ✓ for success. Hints have none. Not read aloud as content.
  2. Message--text-body-sm; --color-fg-muted for hints, --color-danger-fg for errors, --color-success-fg for success. One sentence.
  3. Field linkThe control carries aria-describedby pointing at the message's id, and aria-invalid="true" while it is in error (border turns --color-danger-solid).

  • Hint is there before anything is typed, and stays. It never repeats the label.
  • Error replaces nothing: if a field has a hint, the error goes beneath it, and both are in aria-describedby (error first).
  • Success only where it reassures after a check that took a moment, such as checking a photo's type and size before upload. Most fields need none.
  • Counter sits at the end edge for fields with a hard limit (singer name 20, song title 80).

Sizes

Inline messages have one size, the small body style. They follow the field, not the other way round.

When messages appear

  • Errors appear on submit, then update live as the grown-up types, and disappear the moment the value is fine. Never on the first keystroke, never on blur of an untouched field.
  • On submit with errors, focus moves to the validation box; each of its lines links to the field, where the inline message repeats the same words.

Responsive behaviour

  • Messages wrap under their field at any width; the error marker stays aligned with the first line.
  • In a .field-pair each half keeps its own message; at narrow widths the pair's messages may be different heights, and that is fine.
  • The counter stays at the end edge and never wraps onto its own line before the message.

Theming

Hints read --color-fg-muted, errors --color-danger-fg, success --color-success-fg, the counter --color-fg-muted at --text-caption. The invalid field border is --color-danger-solid. No component tokens.

In the night studio the danger ink becomes a soft rose and success a light mint, both at 4.5:1 or better on the night surfaces. The 💙 marker is an emoji and looks the same in both themes.

Accessibility

Role and pattern

Plain text tied to its control with aria-describedby; the control carries aria-invalid="true" while in error. There is no APG widget pattern for this; it follows the APG Providing accessible names and descriptions practice and WCAG 3.3.1 and 3.3.3. Do not give each message role="alert": the summary announces on submit, and a field's description is read when it is focused.

Keyboard

KeyAction
TabSkips the message (it is text); landing on the field reads its label, value, "invalid" and the message.
Enter on a summary linkMoves focus to the field the line describes.

Focus

Messages never take focus. The field's own focus ring (border --color-focus-ring) wins over the invalid border while focused, and the message stays visible under it.

Labelling

The message is a description, not the label: the field keeps its visible <label for>. The 💙 and ✓ markers are CSS content so they are not part of the text; errors are recognisable by their words and position, never by colour or the heart alone.

Motion

Messages appear and disappear without animation, so nothing moves under the grown-up's cursor while typing.

Touch

Not interactive. Keep 8px between the message and the next label so the next field's hit area does not crowd it.

Content

  • Say what to do, with the allowed values: Tempo must be between 40 and 220 BPM., Note 3: midi 96 is outside 48–84 (C3–C6).
  • Use the same words as the matching line in the validation box, so the grown-up recognises it.
  • Never Invalid, Required field or Error:. Never blame: A song needs a title, not You forgot the title.
  • Hints are one short sentence, no full stop needed for fragments: One emoji for the song's art.
