Error page

A whole screen for the rare moment a page cannot be shown at all: a link that leads nowhere, a family-only page opened offline, or something that broke. Twinkle stays calm and the one button always leads back to singing.

Overview

Not in the mocks yet; added for the app shell (unknown routes, uncaught errors) and for family-server pages opened without the server. The mocks handle every expected failure in place instead: a server that is away becomes an empty state that offers solo singing (Who's singing, Duet), the offline songbook gets a banner, a blocked microphone gets the mic-denied dialog, and the tuner shows mic?. Reach for a full error page only when there is no screen left to show.

  • Not found: an old bookmark or a mistyped address.
  • Offline: a page that only exists on the family server (a duet room link, a family song that was never cached) opened with no server.
  • Something broke: an uncaught error in the app. A grown-up gets a short reference to report; the child gets a way back.

Every variant keeps the child singing: the one big button goes to Home or straight to the songbook, both of which work offline.

Anatomy

  1. Twinkle.mascot.mascot-lg, 150px, floating. Always smiling: she is never shown sad or broken.
  2. HeadingThe page's <h1> in --text-h2. Says what happened in a child's words.
  3. MessageOne sentence in --color-fg-muted, extrabold: what happens next.
  4. ActionOne extra-large blue button, a link to a screen that works offline. An optional quiet link below it for grown-ups.

The page is a centred column (--layout-screen-max) with 48px top padding, on the normal page sky with the drifting clouds. No bottom navigation and no back button: the one action is the way out.

Responsive behaviour

  • One centred column at every width, capped at 470px; side padding is --layout-margin.
  • On short landscape phones Twinkle drops to .mascot (110px) so the button stays above the fold.
  • The extra-large button fills the column; the heading wraps to at most two lines at 320px.

Theming

The page sits on the theme's sky (--gradient-sky) and uses only text and button tokens: --color-fg-default heading, --color-fg-muted message, the blue button. Twinkle's gold is identical in both studios, so the page feels the same at bedtime as at breakfast.

Accessibility

Role and pattern

A normal page: <main class="error-page"> with one <h1>, a paragraph and a link styled as a button. No APG widget pattern applies; it follows the APG landmark regions guidance (one main, a skip link). The document <title> says what happened (Page not found — TwinkleTune) so screen-reader users hear it on arrival.

Keyboard

KeyAction
TabSkip link, the main action, then For grown-ups if present.
EnterFollows the action link; opens or closes the grown-up details.
SpaceToggles the grown-up details (<summary>).

Focus

On a client-side route change to an error page, move focus to the <h1> (tabindex="-1") so the heading is announced, then Tab reaches the action.

Labelling

Twinkle is aria-hidden. The action names its destination (Back to Home 🏠, Sing solo ▶). The grown-up reference is plain text that can be selected and copied.

Contrast

Motion

Twinkle floats; the clouds drift. Both stop under prefers-reduced-motion. No shake, flash or "glitch" effect, ever.

Touch

The action is the extra-large 68px button, full column width. The grown-up summary is at least 44px tall.

Content

  • Heading: what happened, as a little story, never a code: This page floated away! ☁️, The family server is napping 😴, Twinkle needs a little rest 💤.
  • Message: what still works and what to do. Every song still works right here.
  • Action: where it goes, with an emoji: Let's sing! 🎤, Sing solo ▶, Back to Home 🏠.
  • Grown-up details: what happened, whether data is safe, what to try, and a short reference. Never a stack trace, never "Failed to fetch" (D19).
  • Never 404, Error, Oops, Something went wrong as a headline, a broken or crying Twinkle, or a red screen.

Sources

Not in the mocks yet; added for the app shell and family-server deep links. It borrows from these mocks, which handle expected failures in place:

  • pages/welcome/default (big Twinkle, centred screen, extra-large action)
  • pages/duet/error and pages/profiles/error (server away: offer solo)
  • pages/songs/offline (offline songbook banner)
  • dialogs/mic-denied/default and pages/tuner/error (device problems stay on their screen)

Drift that applies: grown-up copy says what happened and what to do instead of a raw "Failed to fetch" (D19); muted text uses --color-fg-muted (D02); the quiet link uses the dotted --color-border-strong underline (D24). See the drift log.
