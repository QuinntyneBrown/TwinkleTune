Textarea

The multi-line field. In TwinkleTune it holds a song's phrases and notes as JSON in the song editor, so its default face is monospace; a prose face is ready for longer grown-up notes.

Overview

Use a textarea when the answer runs over more than one line. There is exactly one in the mocks: Phrases & notes in the family-server song editor, where a grown-up writes or pastes a song as note data ({ midi, start, dur, syll } per note, grouped into phrases). A child never sees it.

  • Code (textarea.field, the default) is monospace at 12px with spell-check off, because it holds JSON. Lines must not wrap mid-token, so it scrolls horizontally rather than reflowing.
  • Prose (textarea.field with font-family reset to the body face and a .field-counter) is for sentences, such as where a family song comes from. Not in the mocks yet; added for the family-server managers.

For one line, use a text field. Wrap the textarea in a form field for its hint, error and counter.

Anatomy

  1. Label.field-label, Baloo 2 bold 16px, a short noun.
  2. Content--font-family-mono at --font-size-xs (12px, the type floor) for note data; the body face at 16px for prose.
  3. Resize gripVertical only (resize: vertical). Minimum height 160px (2.5 × --size-art), about ten lines of JSON.
  4. Hint.field-hint under the field, linked by aria-describedby. The format rules live here, not in the label.

Variants

Code (note data)

As in the song editor's edit state, label and all. The system moves the parenthesis into a hint (see Do and don't).
HTML
<label class="field-label" for="song-phrases">Phrases &amp; notes</label>
<textarea class="field" id="song-phrases" spellcheck="false"
          aria-describedby="song-phrases-hint">…</textarea>
<p class="field-hint" id="song-phrases-hint">JSON. midi 60 = middle C; times in beats.</p>

Sizes

One size: a 160px minimum that the grown-up can drag taller.

States

Hover and focus forced with data-state. Read-only is how a seed song's notes are shown: seed songs are bundled and cannot be edited.

Both themes

  • Invalid marks the field and lists each problem under it, naming the note and the fix. The mocks show these problems only in the dialog's validation box; the system adds the field link (see form layout).
  • Nothing typed is ever cleared on a failed save. The song editor's invalid and failed states keep every character.

Responsive behaviour

  • Full width of the song editor (.modal-wide, up to 440px). The dialog scrolls (max 84vh); the textarea grows inside it, never past the viewport.
  • Code does not wrap: long note lines scroll sideways inside the field, so the page itself never scrolls horizontally at 320px.
  • Prose wraps normally; start at 3 rows and let the grip add more.

Theming

Shares every token with the grown-up text field: well --color-bg-surface-sunken, edge --color-border-strong, text --color-fg-default. Only the type differs: --font-family-mono and --font-size-xs. No component tokens.

Accessibility

Role and pattern

Native <textarea>, which is a multi-line text box. No APG widget pattern applies; follow the WAI Forms tutorial.

Keyboard

KeyAction
Tab / Shift+TabMoves into and out of the field. Tab never inserts a tab character, so the field is never a keyboard trap; indent JSON with spaces.
EnterInserts a new line. It does not submit the form.
EscCloses the song editor dialog. What was typed is lost only after the grown-up has chosen Cancel or Esc, never on a failed save.

Focus

Same as the text field: the edge turns --color-focus-ring with a 2px outer ring.

Labelling

A short visible label (Phrases & notes) plus a hint for the format, joined with aria-describedby. Problems listed under the field are added to aria-describedby too, so a screen reader hears them on focus.

Motion

None. Resizing follows the pointer.

Touch

The field is far larger than any target minimum. The resize grip is small, so it is a convenience, not the only way: the field also scrolls, and on touch screens it can stay at its minimum height.

Content

  • Start new songs from a working template (the song editor seeds three notes: La la la), never an empty box.
  • Problems name the note and the fix in grown-up words: Note 3: duration must be positive., The melody spans 36 semitones — keep it within 16.
  • Turn off spell-check (spellcheck="false") for code; leave it on for prose.
  • Keep the label to the field's name; move rules and units into the hint.
