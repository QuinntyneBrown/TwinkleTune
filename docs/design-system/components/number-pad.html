Number pad

Three big rounded answer keys under the parent gate's sum. A grown-up taps the right one to get into the Grown-Ups Corner; any other key gives a little shake and nothing else.

Overview

The number pad is the answer part of the Parent gate: the arithmetic challenge in front of the Grown-Ups Corner and every destructive action. The dialog asks a sum (What is 6 + 3?) and offers three answers as keys, one of them right. It is a speed bump for small fingers, not a lock, so it never counts tries, never locks out and never says "wrong".

  • Use it only inside the parent gate. To type a number (tempo, a duet room code) use a text field or the duet code input.
  • Always three keys, shuffled, with the right answer in a different position each time. Two would be a coin toss; more would crowd the dialog.
  • The distractors are near misses (8 and 11 for 6 + 3), so a guessing child is unlikely to land on the answer while an adult reads it at once.

Anatomy

  1. Question.gate-question: --font-size-lg, full-strength ink, inside the dialog's muted lead line. It labels the key group.
  2. Key.num: a 56px square (--size-avatar) with 16px corners (--radius-md), Baloo 2 extra-bold at --font-size-2xl on --color-bg-subtle.
  3. Row.num-row: centred, 8px gaps (--space-2), 16px above.
  4. LipA 4px solid offset in --color-border-default (--lip-small). It drops to 1px while pressed, like the toy buttons.

Variants

There is one variant: three keys in a row inside the parent gate dialog. The sum changes every time the gate opens.

Sizes

The number pad has one size: 56px keys, above the 52px child target, so a grown-up's thumb lands cleanly on a phone.

States

Hover, focus and pressed are forced with data-state. Shake is the real class the app adds to a key that is not the answer; it plays twice and is removed.

Answer key

Both themes

  • Right answer has no look of its own: the gate closes at once and the Grown-Ups Corner (or the destructive confirm) opens in its place.
  • Shake moves the tapped key 8px left and right, twice, over --duration-slow. The question stays, nothing is counted, and every key stays enabled. A screen reader hears "Try another answer" from a polite status line.
  • No disabled or busy state. The check is local arithmetic and acts at once; no key is ever greyed out.

Responsive behaviour

  • The row is 3 × 56px plus two 8px gaps, 184px, which fits the 340px dialog at every viewport down to 320px.
  • The dialog is a centred card at every width; the keys never stretch to fill it and never stack.
  • At 200% zoom the digits grow with the root size and the keys stay square; two-digit answers (11, 12) still fit on one line.

Theming

Keys read --color-bg-subtle (body), --color-bg-subtle-hover (hover), --color-fg-default (digit) and --color-border-default (lip). There are no component tokens; a theme changes the semantic tokens and the keys follow.

In the night studio the subtle tint becomes a raised navy, a step lighter than the dialog surface, so the keys still read as pressable blocks; the lip darkens with the border token.

Accessibility

Role and pattern

Three native <button type="button"> elements (APG Button) in a role="group" labelled by the question, inside an APG modal dialog. The shake is paired with a visually hidden role="status" line so the feedback is not motion only.

Keyboard

KeyAction
Tab / Shift+TabMoves between the three keys and the Back to singing link; focus stays inside the gate dialog.
Enter, SpaceAnswers with the focused key. A different answer shakes the key and keeps focus on it.
EscSame as Back to singing: closes the gate and returns focus to the button that opened it.

Focus

When the gate opens, focus moves to the first key so the question is read as the group's label. The shared 3px --color-focus-ring at a 3px offset follows the 16px corners.

Labelling

The digits are the names. The group is labelled by the element holding the question (aria-labelledby), so a screen reader says "To continue, answer: What is 6 plus 3? group, 8, button".

Motion

The shake runs over --duration-slow (400ms), twice. Under prefers-reduced-motion the duration is zeroed and the key does not move; the status line still says "Try another answer". The press drop uses --duration-fast.

Touch

56px keys with 8px gaps exceed the 52px child target. Taps act on release (click), so sliding off a key cancels it.

Content

  • The question is a single-digit sum with a two-digit answer at most: What is 6 + 3?. Use +; never subtraction, times tables or word problems.
  • Distractors are within three of the answer and never negative.
  • No message on a different answer beyond the shake and the hidden "Try another answer". Never "Wrong", "Incorrect" or a count of attempts.
  • The way out is always offered and always kind: Back to singing.
