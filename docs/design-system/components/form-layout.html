Form layout

How fields sit together in the family-server dialogs: one column, short fields paired, Preview and Save sharing the action row, and one gentle box that lists what still needs fixing.

Overview

Every form in TwinkleTune lives in a grown-up dialog behind the parent gate: the singer editor, the avatar editor and the song editor. They share one layout: a single column of form fields, short related fields paired on one row, an action row, and a quiet Cancel link under it. When something needs fixing, one box above the actions lists it.

  • Single column: the default; the avatar and singer editors.
  • Field pair (.field-pair, from the mocks): two short fields side by side at every width: Emoji + Tempo, Difficulty + Art style.
  • Responsive row (.form-row.form-row--2, new): two fields that stack below 640px. For wider grown-up pages.
  • Group (fieldset.form-group, new): related checkboxes, radios or fields under one <legend>.
  • Action row (.field-actions, from the mocks): buttons share the row equally. .form-actions (new) is the same but wraps.
  • Validation box (.errors, from the mocks): the problems as a list. .form-summary (new) adds a heading and links to each field.

The full guidance on validation timing and submit behaviour is in the Forms pattern.

Anatomy

  1. TitleThe dialog's <h3>, which labels the dialog: New song 🎵, Edit “Frère Jacques”.
  2. FieldLabel above control, 12px between one field and the next.
  3. Field pair.field-pair: two equal columns, 8px apart.
  4. Validation box.errors: --color-danger-bg, --color-danger-fg, --radius-md, bold 14px. Hidden until there is something to fix.
  5. Action row.field-actions: 16px above, buttons share the row. White secondary first, blue primary last.
  6. CancelA quiet link under the row. It keeps nothing and asks nothing.

Sizes

Layouts take their dialog's width: 340px standard, 440px for the song editor (.modal-wide).

Responsive behaviour

  • Forms are one column at every width, inside a dialog no wider than 440px. Dialogs stay centred cards on phones (they are not bottom sheets; mocks README, open question 1) and scroll inside when taller than 84vh.
  • .field-pair stays two-up even at 320px, so only pair fields with short values (an emoji, a number, a select with short options). Each half is then about 120px.
  • .form-row--2 is one column below 640px (40rem) and two above; use it on wide grown-up pages, not in dialogs.
  • .field-actions keeps both buttons on one row with equal widths; labels must fit about 130px each at 320px (Preview ▶, Create ✨ do). .form-actions wraps when they would not.

Theming

Layout classes carry no colour except the validation box, which uses --color-danger-bg and --color-danger-fg; both are re-tuned in the night studio and keep 4.5:1. Spacing uses --space-2 (pairs, actions), --space-3 (between fields) and --space-4 (above actions) in both themes.

Accessibility

Role and pattern

A <form> in an APG modal dialog (role="dialog", aria-modal="true", labelled by its <h3>). Groups are <fieldset> + <legend>. Use novalidate and the system's messages instead of the browser's bubbles, which cannot be styled or made gentle.

Keyboard

KeyAction
Tab / Shift+TabMoves through fields in visual order: left before right in a pair, then the actions, then Cancel. Focus stays inside the dialog.
Enter (in a single-line field)Submits: same as the primary button.
EscCloses the dialog, like Cancel; focus returns to the button that opened it.
Enter on a summary linkMoves focus to that field.

Focus

On open, focus goes to the first field. On a failed Save, focus moves to the validation box (tabindex="-1") so its heading and list are read; each link then moves to its field. After a successful save the dialog closes and focus returns to the opener.

Labelling

Every field has a visible label, the dialog is named by its title, and each problem names its field (Note 3: …, Tempo …). Fields with a problem get aria-invalid="true" and point at their message with aria-describedby.

Motion

The dialog pops in (.pop); the validation box appears without animation. Reduced motion removes the pop.

Touch

Small buttons in the action row are 44px tall with 8px between them; Cancel sits 16px below so it is not hit by mistake.

Content

  • Dialog titles say what is being made or changed: New song 🎵, Edit Bea, New avatar 😊.
  • The primary button names the result with a little sparkle: Create ✨, Save ✨, Add singer ⭐. The secondary is a different action, never a second Save.
  • The validation box opens gently (A few things to fix before saving:) and lists each problem as one sentence with its fix.
  • Failures say what happened and what to do, in grown-up words. Never the browser's raw text.
