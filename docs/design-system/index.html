What this is

The visual and interaction language of TwinkleTune, written down once. Every value here was mined from the 92 mocks in docs/mocks, normalised into tokens, checked for WCAG 2.2 AA contrast in both themes, and documented the way a design-system kit is: foundations, one page per component with every state, and patterns that compose them.

Three product principles shape every page: encouragement only (no red crosses, no “wrong”, silence is not a wrong note), one big obvious action per screen, and chunky, toy-like controls in big rounded type.

How to use

  1. Link the tokens, then the components: <link rel="stylesheet" href="tokens/tokens.css"> and <link rel="stylesheet" href="assets/components.css">.
  2. Use the class names exactly as each component page's Code section shows. State comes from real attributes (disabled, aria-pressed, aria-current, aria-invalid, aria-busy); data-state is for documentation only.
  3. Never write a raw colour, size or duration: read a semantic token (--color-*, --space-*, --duration-*). Re-skin a component through its component tokens (--btn-bg …).
  4. Generate platform constants from tokens/tokens.json (DTCG format; dark values under $extensions).
  5. Pair new foreground and background tokens in tokens/contrast-pairs.json and run the contrast check.

Light (“sky studio”) is the shipped product. Dark (“the studio at night”) is defined for every token and demonstrated on every page with the ☾ Dark toggle, but the app does not ship it yet.
