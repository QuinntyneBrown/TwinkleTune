Spacing

A 4px scale that gives every screen room to breathe. Space inside a thing is always smaller than the space between things, so a child sees the groups before she reads a word.

WCAG 2.2 AATokens --space-*4px gridStatus: stable

Overview

Every margin, padding and gap comes from --space-*. The scale is a 4px grid with a 2px half-step for hairline gaps. The mocks used 6, 10, 14, 18, 22, 26, 30, 34 and 46px; each was snapped to its nearest step (D11), which keeps the same airy feel with sixteen values instead of thirty.

Spacing never scales with the viewport. A breakpoint may switch a layout token (gutter, margin) to a larger step, but the child screen keeps the same rhythm on a phone and a tablet.

--space-7 (28px) exists for one job: the top padding of a screen and a dialog, where 24px felt cramped under the top bar and 32px pushed Twinkle too low. --space-32 is the clearance above the floating bottom nav so the last card is never hidden behind it.

Inside versus between

The one rule: the space inside a group is smaller than the space between groups. Proximity does the grouping, so screens need fewer dividers and fewer words.

Usage

  • Use gap on a parent (.stack, .cluster, .cta-row) instead of margins on children. .stack-sm and .stack-lg switch the gap to --space-2 and --space-6.
  • Never invent an in-between value (6px, 10px, 14px). If 12px is too tight and 16px too loose, the grouping is wrong, not the number.
  • Between a heading and the content it labels, use less space than above the heading.
  • Touch targets need room as well as size: keep at least --space-2 between small targets (mini buttons, row icon buttons) so a small finger does not catch two at once (D23).
  • Leave --space-32 at the bottom of any scrolling screen that has the bottom nav; leave --space-10 on screens without it (.screen--nonav).
