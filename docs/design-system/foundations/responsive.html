Foundation

Responsive

Every child screen is one centred column, at most 470px wide, from a small phone to a desktop monitor. Nothing rearranges between sizes, so the big obvious action is always in the same place. Breakpoints exist only for grown-up pages, the docs and marketing.

Overview

  • Mobile first. Base styles target a 360px phone held in a small hand. Wider screens add margin around the column, not more columns.
  • One column, always. .screen is capped at --layout-screen-max (470px) and centred. A child who sings on a tablet one day and a phone the next finds every button where she left it.
  • Touch is the primary input. Anything a child taps is at least 52px (--target-child). Hover is a bonus, never the only way to discover something.
  • Grown-up surfaces may grow. The family-server managers, these docs and the marketing site use the 4 / 8 / 12-column grid on Layout.

The one column

Your songs are tuned and ready. Let's make today sparkle! ✨

Sing a Song

Every song in YOUR key 💙

Let's go! ▶🎤
The Home column at its 470px cap. At 360px the same parts stack in the same order; at 1280px the sky simply gets wider.
  • Side padding is --layout-margin (20px) on child screens; the bottom keeps --layout-bottomnav-clearance so the floating nav never covers the last card.
  • Two-up grids inside the column (.tiles, .cta-row) stay two-up at every width; at 360px each half is still wider than 150px.
  • Type does not scale with the viewport. Sizes are fixed steps in rem so browser zoom and the device's text-size setting work.
  • Use 100dvh for full-height screens so mobile browser chrome does not clip the bottom action, and add env(safe-area-inset-bottom) under fixed parts.

Touch and pointer

52px child controls; a 44px grown-up button; a 24px mini button that keeps 8px from its neighbours.
Who taps itMinimumExamples
A child, primary action52px (--target-child)Toy buttons (56–68px), icon buttons, play buttons, avatar picks, number keys, bottom-nav items

Secondary glyph controls24px (--target-min) with 8px spacingThe 🏆 and 🎤🎤 Duet mini buttons (D23)
  • No hover-only affordances. Badge hints shown by title on hover are also reachable by tapping the badge; tooltips open on focus and tap.
  • Actions fire on release (click), so a child who lands on the wrong button can slide off it.
  • Singing needs no gestures. On the Sing screen the voice moves the star; the only touch targets are Pause and, in the countdown, nothing at all.
  • No orientation lock. Landscape shows the same column centred; the pitch stage keeps its height.
  • Drag has an alternative. The mic-timing slider is a native range input, adjustable with arrow keys and taps.

Usage

  • Write min-width queries in rem (48rem, 64rem) and only for grown-up layouts. A child screen that needs a media query is usually trying to do too much.
  • Prefer intrinsic layout (flex-wrap, minmax(), min(100%, …)) over breakpoints.
  • Shorten words before shrinking type. A button label that wraps at 360px is too long.

Accessibility

  • Reflow (1.4.10): one column at 320px with no two-dimensional scrolling, except data tables inside .table-wrap.
  • Resize text (1.4.4): all sizes are in rem; 200% text never clips a button label or hides the action.
  • Orientation (1.3.4): portrait and landscape both work.
  • Target size (2.5.8): every target is at least 24px; child targets 52px. See Accessibility.
  • Focus not obscured (2.4.11): the bottom nav and toasts never cover the focused element; screens keep bottom clearance for the nav.

Tokens

Responsive owns no tokens. Breakpoints, columns, gutters, margins and the screen cap are on Layout; target sizes and control heights on Accessibility.
